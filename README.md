# AutoFlip: Cloudflare Pages и VK ID

Эта ветка — отдельный безопасный этап миграции. Главная страница по-прежнему показывает заглушку и **не публикует игру**. Тестовый интерфейс входа находится по адресу `/login/`.

## Настройка Pages

Проект Pages подключён к репозиторию `flowbs00-lang/autoflip` и ветке `cloudflare-vk-auth`.

- Build command: `exit 0`
- Build output directory: `cloudflare`
- Root directory: пусто (корень репозитория)
- Production URL: `https://autoflip.pages.dev`
- VK ID callback: `https://autoflip.pages.dev/auth/vk/callback`

Каталог `/functions` должен оставаться в корне репозитория: Cloudflare автоматически собирает из него Pages Functions.

## D1

1. Создать базу `autoflip-prod` в Cloudflare D1.
2. Добавить к Pages-проекту D1 binding с именем `DB`.
3. По порядку выполнить все SQL-файлы из `migrations/` в консоли D1. Для этого обновления последняя миграция — `0009_security_rate_limits.sql`. Миграции `0008` и `0009` также безопасно и однократно применяются Pages Functions при первом запросе и отмечаются в таблице `app_migrations`; это резервный путь для уже работающего проекта без постоянного API-токена.
4. Перезапустить deployment, чтобы binding применился.

## Реализовано

- авторизация через официальный VK ID;
- уникальный никнейм и внутренний ID игрока;
- серверные сессии в защищённых HttpOnly-cookie;
- схема D1 для аккаунтов, сессий и облачных сохранений;
- защита входа и запросов от подделки;
- закрытый доступ к незавершённой игре;
- мобильный интерфейс входа и создания профиля.
- закрытая регистрация: существующие аккаунты входят, новые создаются только по списку тестировщиков;
- отдельные версии согласий и добровольная настройка публичного профиля;
- юридические страницы в каталоге `/legal/`.

## Закрытое тестирование

Публичная регистрация по умолчанию выключена. Это серверное ограничение, поэтому его нельзя обойти прямым вызовом API.

- `BETA_TESTER_VK_IDS` — VK ID приглашённых тестировщиков через запятую;
- `PUBLIC_REGISTRATION_ENABLED` — оставить пустым или `false` до юридической и инфраструктурной готовности;
- значение `true` разрешит регистрацию всем и должно устанавливаться только перед согласованным публичным запуском.

Уже существующие в таблице `users` аккаунты продолжают входить. Перед deployment применить миграции до `0009_security_rate_limits.sql`; сервер также безопасно создаёт недостающие служебные таблицы при первом обращении.

`ADMIN_PLAYER_IDS` — необязательная переменная окружения со списком внутренних ID модераторов через запятую. Аккаунт владельца `AF-VH8KEHQ3GRCC` имеет доступ к панели модерации автоматически.

Страницы документов пока помечены как проекты. До публичного запуска заполнить `/legal/operator/`, провести проверку юриста, настроить российскую инфраструктуру персональных данных и только затем включать регистрацию.

## Безопасность

Используется OAuth 2.1 с PKCE. Закрытый ключ VK ID не нужен и не хранится ни в GitHub, ни в браузере, ни в Cloudflare. Сервер самостоятельно перепроверяет краткоживущий токен через VK ID и выдаёт отдельную случайную сессию AutoFlip.

Pages Functions централизованно ограничивают частоту входа, сообщений, жалоб, обращений, создания кланов, изменения никнейма, сохранений, создания платежей и административных запросов. При аномальной активности аккаунт или ежедневно меняющийся хэш IP временно блокируется; исходный IP и User-Agent в D1 не сохраняются. Журнал доступен администратору через `GET /api/security/events` и автоматически очищается через 30 дней.

Для production добавьте секрет `SECURITY_HASH_SECRET` длиной не менее 32 случайных байт в **Settings → Environment variables and secrets** проекта Pages. Он не должен попадать в GitHub. Без переменной защита продолжит работать с резервным значением, но отдельный секрет делает псевдонимизацию IP существенно надёжнее.

CSP без `unsafe-inline` применяется ко всем служебным, юридическим и API-страницам. Временное исключение оставлено только для старого игрового интерфейса `/app/*`; VK ID на страницах входа требует лишь inline-стили, но inline-скрипты там запрещены. Следующий этап ужесточения CSP — вынести оставшиеся скрипты, обработчики и динамические стили игры из `cloudflare/app/index.html` в отдельные файлы.
